# 调研

用户让 AI 联网搜索、搜 GitHub、对比竞品或参考软件并整理结果时，结果写在这个文件夹里，不只留在对话里。

和 [investigations/](../investigations/) 的区别：这里是**外部**的信息（别人的项目、文档、产品）；对我们自己的应用做的排查、实测和验收放 investigations/。

## 规则

- **一个主题一个文件**：`<主题>.md`，英文小写、短横线连接，例如 `windows-dynamic-island-apps.md`。同一主题再查一次时更新原文件，加一节带日期的新结果，不另建文件。
- **先写结论**：开头写日期、要回答的问题（用户原话的意思）、搜索范围（搜了哪些站点、关键词、GitHub 的筛选条件），然后马上写结论和建议；细节、对比表放后面。
- **每条事实带来源**：写链接。会变的数字（star 数、版本号、价格、最后更新时间）注明查询日期。没找到可靠来源的写「未核实」，不当成事实写。
- **不搬别人的东西**：只写摘要和自己的分析，不大段复制文章或代码；截图、录音、下载的仓库不进仓库，放本机并写明位置（例如 `E:\Projects\design-refs\...`）。
- **和任务挂钩**：调研是为某个任务做的，任务的 `## 结论` 写一两句话并链接到这里；调研得出要做的事，用 `pnpm tasks add` 建任务，在这里链接任务编号。
- **过时了不删**：结论被后来的调研或决定推翻时，在开头加一行说明并链接到新的文档或任务。

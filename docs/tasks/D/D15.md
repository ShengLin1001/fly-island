## 说明

Rust 命令返回的报错是一段写死的文字，前端原样显示，所以总有一种界面语言的用户看到另一种语言。现在是中英混用：日历（`calendar/sources.rs`）、邮件（`mail/`）、翻译（`translation/mod.rs`）、用量环（`agent_status/plan_usage.rs`）等模块是中文；cc-connect（`cc_connect/`）和 Bark 推送（`phone_push/mod.rs`）在 2026-11-09 刚改成英文。截至那天，`src-tauri/src/` 下约 60 个文件有中文字符串（含设置清单这类本来就该双语的）。

改成：命令出错时返回错误码和参数（例如 `{ code: "credential.save", detail }`），前端在 i18n 里按码给出中英文文案；外部服务和系统返回的原文（cc-connect 的输出、HTTP 错误、IO 错误）作为参数原样带上，不翻译。

先定格式和前端的通用显示函数，再按模块逐个迁移。「Windows 凭据」几句在 phone_push、calendar、plan_usage、translation 里重复，适合先收成一处共用。

## 验收

- 定下错误的序列化格式和前端解析函数，写进 [contracts.md](/docs/architecture/contracts.md)；旧格式（纯字符串）前端仍能显示。
- 用户可见的原生报错在中文、英文界面下各显示对应语言；外部原文作为附带信息保留。
- cc-connect、Bark、日历、邮件、翻译、用量环这几个模块迁移完；其余模块列出清单，逐个做或拆子任务。
- Rust 测试断言错误码而不是文案。

## 备注

- 2026-11-09 用户在两种做法里选了这一种（另一种是全部改成英文，一个提交能做完，但中文用户会看到英文报错）。
- 起因是 PR #27 的 cc-connect 报错是中文；合入后已先改成英文（`e5b67b1`），Bark 也一并改了（`98ff4651`）。迁移时这两处照同样的格式处理。
- 插件清单（`plugin_host/builtin.rs` 的 `zh-CN` / `en` 字段）本来就是双语，不在范围内。

## 说明

微信提醒现在只靠任务栏闪动（`HSHELL_FLASH`）显示「微信有新提醒」，没有联系人和内容。外部项目用 UI Automation 读微信 4.x 的会话列表拿到联系人、摘要和未读数（调研见 [wechat-message-content.md](/docs/research/wechat-message-content.md)）。我们 2026-10-19 只测过最小化状态，读到 0 条文字；关到托盘这种最常见的状态没测过，它决定这件事值不值得做。

第一步只做实测，需要用户在自己电脑上登录微信。用仓库里的只读探测工具，它只输出控件和文字的数量，不输出聊天内容：

```powershell
# 1. 微信主窗口开着时记下窗口句柄；关到托盘后窗口还在，只是隐藏，句柄不变
$h = (Get-Process -Name Weixin,WeChat -ErrorAction SilentlyContinue | Where-Object { $_.MainWindowHandle -ne 0 } | Select-Object -First 1).MainWindowHandle
# 2. 每种状态各跑一次
cargo run --manifest-path src-tauri/Cargo.toml --example wechat_accessibility_probe -- --window-handle $h
```

四种状态：主窗口在前台、被别的窗口挡住、最小化到任务栏、关到托盘（点右上角 ×）。每种状态记下 `windowVisible`、`windowMinimized`、`namedListItems`、`namedTextControls`、`bounded`。

## 验收

- 四种状态的探测结果记在 `## 结论`，写明微信版本
- 关到托盘时 `namedListItems` 大于 0：建新任务做接入（任务栏闪动后读一次会话列表，读到就显示联系人和摘要，读不到退回「微信有新提醒」；单独开关、默认关闭，同步改 `docs/features/wechat-reminders.md` 里「不读取可访问性文本」的说法）
- 关到托盘时读不到：在这里写明，`drop` 并说明原因

## 备注

- 不照外部项目每 1–2 秒轮询：空闲时的 CPU 是 D1 关心的，闪动触发读一次就够。
- 群聊只能拿到群名，拿不到具体是谁发的；摘要会被微信截断，图片、语音只有类型提示。
- 2026-11-09 不做：电脑版微信 4.x 没有干净可靠的来源：本机实测 UIA 四种窗口状态都读不到（要先开讲述人），注入和数据库违背项目原则，手机转发覆盖面太小。详见 /docs/research/wechat-message-content.md「为什么不做」

## 结论（2026-11-09）

微信 4.1.15.56，用户在本机跑 `wechat_accessibility_probe`：前台、被遮挡、最小化、关到托盘四种状态都只有 3 个窗口外壳控件，`namedListItems` 和 `namedTextControls` 都是 0；`FindAll(Descendants)` 也是 0。微信 4.x 要检测到屏幕阅读器（讲述人）才交出控件树，所以这条路对普通用户不可用。决定不做，没有再用讲述人复测。完整调研和原因见 [wechat-message-content.md](/docs/research/wechat-message-content.md)。

# 岛屿展开 / 收起时的元素抖动排查

日期：2026-11-09。代码基线：`c955d76`。

## 结论

展开和收起的 560ms 过程中，岛屿上的文字会左右（以及上下）来回抖动 0.5–1 个设备像素，字形也在逐帧变形。**直接原因是整个岛屿外壳在 `transform: scale(...)` 下同时做宽高过渡**：

- 外壳 `.island` 的宽高在动画中逐帧取小数值；内容层 `.island__collapsed` / `.island__expanded` 用 `left: 50%` 居中，它们在外壳**局部坐标**里的偏移也是小数，被浏览器先在局部坐标里对齐到整像素，再乘以缩放系数（默认 0.89 / 0.91）投到屏幕上。对齐误差被缩放后不再落在设备像素上，每帧取整方向不同，于是文字在理论上静止的位置附近来回跳。
- 缩放系数是否在过渡（F14 的改动）不是关键：收起态和展开态缩放相同（都为 0.91）时抖动依旧；缩放为 1 时同样的宽高动画完全不抖。
- 默认设置的两个缩放都不是 1，所以**所有使用默认缩放的用户都会遇到**。

把缩放从 `transform: scale` 改成 `zoom` 后，布局直接在缩放后的尺寸里进行、在设备像素上对齐，抖动基本消失（见下表）。这是目前有实测支持的修复方向，但有副作用需要评估，见「修复方向」。

## 测量方法

- 最小复现页：[island-jitter-fixture.html](island-jitter-fixture.html)，复制 `IslandShell.css` 中外壳和两层内容的过渡规则（宽、高、圆角、`--island-scale` 560ms；内容层 `top` 的 6px 滑动），各放一行中英文混排文字。为只看位置，内容层的透明度固定为 1。
- 用 Playwright 的 Chromium，视口 820×460，`deviceScaleFactor: 1.5`（与此前展开掉帧排查的设备像素比一致），收起宽度 300px（按 `alignCollapsedIslandWidth` 的规则，在 1.5 倍下左缘落在整设备像素上）。
- 切换 class 后暂停全部动画，每 8ms 用 `currentTime` 定位一帧并截图，计算文字墨迹（亮度 > 60 的像素）的加权中心，与 `getBoundingClientRect` 给出的理论中心相减，得到「渲染偏差」。理论位置平稳时，偏差应保持不变；偏差来回跳就是抖动。
- 统计区间：展开取 320ms 之后（此前内容被尚未展开的外壳裁掉一部分，中心不可比），收起取 120ms 之后。

## 结果

| 条件 | 方向 | 偏差范围（设备 px） | 相邻帧跳动 > 0.3px 的次数 | 字形墨迹总量波动 |
| --- | --- | ---: | ---: | ---: |
| 现状：`transform: scale` 0.89 → 0.91 | 收起 | 1.60 | 19 / 61 帧 | 2.99% |
| 现状：`transform: scale` 0.89 → 0.91 | 展开 | 0.66 | 6 / 36 帧 | 0.54% |
| `transform: scale` 两态都为 0.91 | 收起 | 1.10 | 17 / 61 帧 | 0.78% |
| `transform: scale` 两态都为 0.91 | 展开 | 0.72 | 5 / 36 帧 | 0.60% |
| 缩放为 1（对照） | 收起 | 0.00 | 0 | 0.01% |
| 缩放为 1（对照） | 展开 | 0.02 | 0 | 0.04% |
| `zoom` 0.89 → 0.91 | 收起 | 0.27 | 0 | 0.97% |
| `zoom` 0.89 → 0.91 | 展开 | 2.05 | 1 | 2.50% |
| `zoom` 两态都为 0.91 | 收起 | 0.72 | 1 | 1.55% |
| `zoom` 两态都为 0.91 | 展开 | 0.01 | 0 | 0.04% |

同期理论中心在统计区间内只移动约 0.02 设备像素，所以表中的偏差范围几乎全是渲染误差。逐帧数据里还看到：现状展开在 528ms 处文字纵向一次跳 0.8 设备像素，与缩放的最后一点插值落定同时发生。

`zoom` 0.89 → 0.91 展开那一行的 2.05px 不是来回抖，而是一次单向变化：`zoom` 过渡时字号随之逐帧变化，字号的取整让文字在某一帧整体跳一下。缩放不过渡、或两态缩放相同时没有这个问题。

## 相关提交

- `e1e1163`（11-04）`alignCollapsedIslandWidth`：把收起宽度微调到「居中后左缘落在整设备像素」。它的计算没有考虑 `--island-scale`：缩放不为 1 时，真正落在屏幕上的左缘是 `410 − 宽度 × 缩放 / 2`，这次微调对默认缩放基本无效。它的前提（合成器在动画结束时把图层对齐到整像素）在下一条提交后也不再成立。
- `cfeaed4`（11-07，F14）：缩放的过渡从合成器上的 `transform` 改到主线程逐帧插值 `--island-scale`，解决动画中的文字模糊。主线程逐帧重绘让上面的取整误差每帧都直接画出来。本次测量里暂停后定位的帧都在主线程绘制，所以**无法用这一方法比较 F14 之前合成器动画的实时表现**；但「两态缩放相同仍抖」说明宽高动画加非 1 缩放本身就足以产生抖动。

## 修复方向

1. **用 `zoom` 代替 `transform: scale`（推荐先试）**。测得的抖动基本消失，文字仍是逐帧按实际尺寸绘制，不会回到 F14 之前的模糊。需要核对：
   - Rust 命中测试（`island/passthrough.rs`）假定「基准尺寸 × 缩放、顶部居中」的盒子；`zoom` 的视觉盒子相同，但 `transform-origin: top center` 不再起作用，要确认居中仍然成立（外壳是舞台 flex 居中的，`zoom` 后的布局宽度本身就缩放了）。
   - Chromium 128 起 `zoom` 按标准化语义计算，`getBoundingClientRect`、`offsetWidth` 等返回值要逐一确认：收起栏插槽宽度、Agent 提醒行高、消息新到行高这些用测量结果算岛屿尺寸的地方（`useCollapsedSlots`、`expandedHeight.ts` 的输入）不能被重复缩放。
   - `zoom` 过渡会让字号逐帧变化（上表展开那一行）。可以让 `zoom` 不过渡，只在两态缩放不同的瞬间切换；或保留过渡、接受一次整像素跳动。两种都要在 `pnpm tauri dev` 里实际看。
2. **只在缩放为 1 的层上做宽高动画**：例如外壳形状用 `clip-path` 或单独的背景层做动画，内容层固定在舞台坐标里不随外壳宽度重新布局。改动面大于方案 1，只在 `zoom` 行不通时考虑。
3. 不论选哪种，`alignCollapsedIslandWidth` 都应按最终屏幕上的左缘（考虑缩放）计算，或在方案 1 之后重新核对它是否还需要。

## 验证边界

- 测的是最小复现页，不是完整岛屿；液态玻璃的模糊、阴影和光斑层没有包含，它们不影响文字位置，但会影响观感。
- Playwright 的 Chromium 不等于 WebView2，但两者的布局与像素对齐逻辑相同；最终结论要在 `pnpm tauri dev` 或 lane 预览里，在 125% / 150% / 175% 缩放下用逐帧录屏复核。
- 本次只做排查，没有修改应用代码。

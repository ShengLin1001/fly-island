# 收起条歌词有时和播放进度对不上

日期：2026-11-09。播放器：网易云音乐（`cloudmusic.exe`），未装 InfLink 插件。

## 结论

网易云报给 Windows 媒体会话（SMTC）的进度和总时长一直是 0，`LastUpdatedTime` 是空的默认值，所以岛屿只能自己计时（`src/features/media/trackClock.ts`）。歌词不准，是自己计时和实际播放之间的误差：

1. 岛屿每 1.5 秒读一次媒体状态，换歌、暂停、继续都要到下一次读取才被发现，每次随机晚 0–1.5 秒。每首歌、每次暂停误差不同，所以表现为「有时候」不准。
2. 换歌时网易云先报新歌名，约 0.4 秒后才出声；从看到歌名开始计时，歌词会快约 0.4 秒。
3. 在网易云里拖进度条，网易云不发任何事件，进度也仍是 0，岛屿无从得知。
4. 单曲循环重新开始时，没有事件，歌名也不变，岛屿以为还是同一遍，收起条停在最后一句。

## 实测

用一个只读的探测程序订阅网易云会话的 `MediaPropertiesChanged`、`PlaybackInfoChanged`、`TimelinePropertiesChanged`，每 50 ms 记录歌名、播放状态和系统声音有无（时间是记录开始后的秒数）：

| 操作 | 事件 | 声音 |
| --- | --- | --- |
| 下一首 | 8.03 s `MediaPropertiesChanged`（8.14 s 又一次），进度仍为 0 | 8.09 s 静音，8.44 s 出声 |
| 暂停 | 17.09 s `PlaybackInfoChanged` | 17.75 s 淡出到静音 |
| 继续 | 22.53 s `PlaybackInfoChanged` | 22.53 s 出声 |
| 拖进度条 | 无 | 37.5 s、40.8 s 各断一下 |
| 单曲循环从头开始 | 无 | 无变化 |

`TimelinePropertiesChanged` 一次也没有触发。

## 处理

- `src-tauri/src/media_control/events.rs` 订阅所有媒体会话的换歌和播放状态事件，立刻发 `media-session-changed`，带事件时间。换歌只在歌名或歌手变了时才算（封面、专辑更新不算），并在换歌后每 15 ms 看系统声音：先静下来、再出声的那一刻算作新歌开始；300 ms 内没静下来（两首歌连着）或 2 秒内没出声（暂停、缓冲），就用换歌事件的时间。
- 前端收到后立刻读媒体状态（`useMediaSessionChanges`），计时器按事件时间开始、停止（`startClockAt`、`advanceClock`），不再按读取的时间。轮询先发现了新歌也没关系，事件到了会把开始时间校正回去；已经播了很久的歌不会被误判为重新开始。
- 收起条：岛屿自己计时的歌，过了最后一句 12 秒后不再显示最后一句，单曲循环时不会一直停在那里。

拖进度条和单曲循环仍然无法知道：拖完在音乐页点正在唱的那句对齐，或装 InfLink 插件让网易云报告真实进度（岛屿已支持）。
